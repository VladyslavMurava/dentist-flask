# Правила командної роботи

## Гілки

- `main` — стабільна гілка, з неї виконується розгортання на Render.
- Нова функціональність або виправлення — в окремій гілці від `main`:
  `feature/<назва>` або `fix/<назва>`.
- Прямі коміти в `main` заборонені, зміни потрапляють туди лише через Pull Request.

## Pull Request

1. Створити гілку, внести зміни, закомітити з описовим повідомленням.
2. Відкрити Pull Request у `main`, заповнити шаблон: що зроблено, як перевірити.
3. Дочекатися зеленого статусу перевірок GitHub Actions (компіляція, тести).
4. Отримати рев'ю щонайменше одного учасника.
5. Злити через **Merge** після схвалення.

## CI/CD

Workflow `.github/workflows/ci-cd.yml`:

- на кожен Pull Request і push у `main` — встановлення залежностей, компіляція, `pytest`;
- після успішних перевірок у `main` — виклик Deploy Hook Render, який запускає
  автоматичне розгортання нової версії.

Секрети (`RENDER_DEPLOY_HOOK`) зберігаються в GitHub Settings → Secrets, у коді
їх немає.

## Локальний запуск

```bash
pip install -r requirements.txt pytest
set DATABASE_URL=postgresql://...
set HF_TOKEN=hf_...
pytest -q
python app.py
```
